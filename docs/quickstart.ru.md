# Быстрый старт yesh

yesh — небольшой shell на Go для читаемых DevOps- и административных
скриптов.

> **Bash без исторической синтаксической сложности.**

Ниже используется только синтаксис, который поддерживает текущий runtime.
Это не описание будущих встроенных команд или декларативных возможностей.

## Простая проверка служб

Задача: проверить список служб и завершиться с ошибкой, если какая-либо служба
не активна.

### Bash

```bash
services=(nginx sshd)

for service in "${services[@]}"; do
    if systemctl is-active --quiet "$service"; then
        echo "$service is running"
    else
        echo "$service is not running"
        exit 1
    fi
done
```

### yesh

```yesh
services = [nginx, sshd]

for service in services:
    if systemctl is-active service:
        echo service "is running"
    else:
        echo service "is not running"
        exit 1
```

Версия на yesh читается сверху вниз как последовательность обычных фраз:

1. определить список;
2. пройти по каждой службе;
3. проверить успешность команды;
4. вывести результат;
5. явно завершиться при ошибке.

Здесь нет `$service`, `${services[@]}`, `[[ ... ]]`, `then`, `fi`, `do`,
`done` и обязательного `set -euo pipefail`.

## Что меняет yesh

### Значения сохраняют тип

```yesh
services = [nginx, sshd]
for service in services:
    echo service
```

`services` — список, а `service` — одно строковое значение. Список явно
раскрывается языком в аргументы, строка остаётся одним аргументом. Неявного
word splitting нет.

### Команды остаются Unix-командами

```yesh
ps -eo pid=,ppid=,user=,rss=,stat=,comm= | head -n 25
```

Конвейеры, перенаправления и аргументы сохраняют привычную форму Unix. yesh
запускает аргументы напрямую через Go-runtime, не разбирая всю строку ещё раз
через другую оболочку.

### Ошибки видны по умолчанию

Если `systemctl` не запускается или возвращает ошибку, условие `if` ложно.
Если обычная команда завершается с ошибкой вне условия, yesh останавливает
скрипт и указывает исходную строку. `set -e` не нужен.

Явное завершение остаётся явным:

```yesh
if exists /etc/my-service.conf:
    echo "configuration exists"
else:
    echo "configuration is missing"
    exit 2
```

`exists path` — предикат yesh. Это не скрытая shell-проверка и не обещание,
что файл останется доступен после проверки.

## Запуск

Из корня репозитория:

```text
go build -trimpath -o yesh ./cmd/yesh
```

Запуск скрипта:

```text
./yesh examples/service-check.yesh
```

Показать раскрытые команды и ветвления без выполнения:

```text
./yesh --plan examples/service-check.yesh
```

`--plan` удобен при ревью: он показывает векторы аргументов и планируемые
ветвления, не запуская команды.

## Граница проекта

yesh — не режим совместимости с Bash и не Python с коротким способом вызвать
команду. Язык намеренно меньше:

- Unix-инструменты (`grep`, `sed`, `awk`, `ssh`, `systemctl`, `rsync`) остаются
  внешними командами;
- yesh отвечает за читаемый control flow, строки и списки, прямые аргументы,
  ограниченное выполнение и обработку ошибок;
- неподдерживаемые возможности shell — command substitution, `while`, скрытый
  background и вложенный shell — не появляются молча.

Проверка дизайна проста: если новая возможность не делает административный
скрипт легче читать, проверять или безопасно повторять, ей не место в малом
ядре yesh.
