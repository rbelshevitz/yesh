# Быстрый старт yesh

yesh — небольшой язык и интерпретатор на Go для административных и
операционных скриптов, которые легко читать. Это не интерактивная оболочка и
не попытка совместимости с Bash.

> **Bash без исторической синтаксической сложности.**

Ниже используется только синтаксис, который поддерживает текущая версия среды
выполнения.
Это не описание будущих встроенных команд или декларативных возможностей.

## Простая проверка служб

Задача: проверить список служб и завершиться с ошибкой, если активность
какой-либо службы не подтверждена. Нужны доступ к systemd и установленные
службы; замените `nginx` и `sshd` именами служб своей машины.

### Bash

```bash
services=(nginx sshd)

systemctl show --property=Version >/dev/null || exit 1

for service in "${services[@]}"; do
    if systemctl is-active --quiet -- "$service"; then
        echo "$service is active"
    else
        echo "$service active check failed"
        exit 1
    fi
done
```

### yesh

```yesh
services = [nginx, sshd]

systemctl show --property=Version > /dev/null

for service in $services:
    if systemctl is-active --quiet -- $service:
        echo $service "is active"
    else:
        echo $service "active check failed"
        exit 1
```

Сначала отдельная команда проверяет доступ к менеджеру systemd. Её ошибка
останавливает скрипт до сообщений о службах. Если доступ пропадёт позже,
`active check failed` сообщает о неуспешной проверке, а не утверждает, что
служба остановлена. Подробность ошибки остаётся в потоке ошибок.

Версия на yesh читается сверху вниз как последовательность понятных шагов:

1. определить список;
2. проверить доступ к systemd;
3. пройти по каждой службе;
4. проверить результат команды;
5. вывести результат;
6. явно завершиться при ошибке.

Здесь нет `$service`, `${services[@]}`, `[[ ... ]]`, `then`, `fi`, `do`,
`done` и обязательного `set -euo pipefail`.

## Что меняет yesh

### Значения сохраняют тип

```yesh
services = [nginx, sshd]
for service in $services:
    echo $service
```

`services` — список, а `service` — одно строковое значение. Список явно
раскрывается языком в аргументы, строка остаётся одним аргументом. Пробелы
внутри значения не превращаются в дополнительные аргументы.

### Команды остаются Linux-командами

```yesh
ps -eo pid=,ppid=,user=,rss=,stat=,comm= | sort -k 4,4nr
```

Конвейеры, перенаправления и аргументы сохраняют привычную форму Linux-команд. yesh
запускает команды напрямую через среду выполнения на Go, не разбирая всю
строку ещё раз через другую оболочку.

`sort` читает весь вход и сортирует строки по RSS по убыванию. Раннее
завершение читателя, например `head`, может послать писателю SIGPIPE; yesh
считает ошибку любой стадии ошибкой конвейера. Поэтому первый пример
не использует досрочное закрытие канала.

### Ошибки видны по умолчанию

Нулевой код запущенной команды означает true, обычный ненулевой код — false.
Отсутствие команды, невозможность запуска, сигнал, отмена и превышение
времени остаются ошибками выполнения: они не переводят управление в `else`.
Если обычная команда завершается с ошибкой вне условия, yesh останавливает
скрипт и указывает исходную строку. `set -e` не нужен.

Явное завершение остаётся явным:

```yesh
if exists /etc/my-service.conf:
    echo "configuration exists"
else:
    echo "configuration is missing"
    exit 2
```

`exists path` — предикат yesh. Это не скрытая проверка средствами оболочки и не обещание,
что файл останется доступен после проверки.

## Запуск

Из корня репозитория:

```text
go build -trimpath -o yesh ./cmd/yesh
```

Чтобы запускать скрипт как исполняемый файл Linux, установите интерпретатор и
добавьте в начало файла shebang с абсолютным путём:

```text
#!/usr/local/bin/yesh

echo "hello from yesh"
```

Затем добавьте право на выполнение:

```text
chmod +x examples/hello.yesh
./examples/hello.yesh
```

`#!/usr/bin/env yesh` подходит, если `yesh` намеренно установлен в пользовательский
`PATH`. Для systemd-службы лучше явно написать `ExecStart=/usr/local/bin/yesh
/opt/ops/job.yesh`: systemd не предоставляет такое же окружение, как оболочка входа.

Запуск автономного примера, которому не нужны systemd и службы:

```text
./yesh examples/hello.yesh
```

На машине с systemd после выбора имён служб можно выполнить
`./yesh examples/service-check.yesh`. Это проверка состояния, не запуск служб.

Показать раскрытые команды и ветвления без выполнения (доступ к systemd
для этого не нужен):

```text
./yesh --plan examples/service-check.yesh
```

`--plan` удобен при проверке: он показывает списки аргументов, которые yesh
передаст внешним стадиям команд, и планируемые ветвления, не запуская внешние
команды. Встроенные операции yesh, например `publish`, показываются как
планируемые действия со своими параметрами, а не как `argv` внешней команды.

Правило простое: строки `PLAN [...]` показывают список аргументов команды
(`argv`) внешней команды; именованные строки, например `PLAN publish ...`, —
встроенные операции yesh.

## Граница проекта

yesh — небольшой язык для Linux-автоматизации, а не shell и не Python с
коротким способом вызвать команду. Язык намеренно меньше:

- Внешние Linux-инструменты (`grep`, `sed`, `awk`, `ssh`, `systemctl`, `rsync`) остаются
  внешними командами;
- yesh отвечает за читаемое управление потоком выполнения, строки и списки,
  прямые аргументы,
  ограниченное выполнение и обработку ошибок;
- неподдерживаемые возможности оболочки — подстановка команд, `while`, скрытый
  фоновый запуск и вложенный запуск оболочки — не появляются молча.

Проверка дизайна проста: если новая возможность не делает административный
скрипт легче читать, проверять или безопасно повторять, ей не место в малом
ядре yesh.
