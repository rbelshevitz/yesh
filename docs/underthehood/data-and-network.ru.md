# Списки, адреса и CIDR

## Списки — базовый тип

Списки нужны для обычных admin-наборов:

```yesh
hosts = [web-1, web-2, web-3]
services = [api, worker, nginx]
addresses = [10.0.0.10, 10.0.0.11]

for host in $hosts:
    ssh host systemctl restart api
```

Список — упорядоченная последовательность значений. Он не превращается в
строку и не разбивается обратно по пробелам. Повторяющиеся элементы разрешены.

На уровне языка не нужны отдельные «массивы» и «перечисления»: для сценариев
администрирования достаточно одного понятного типа списка.

## IP и CIDR — отдельные значения

IP-адрес не должен оставаться строкой, если yesh выполняет с ним операции:

```yesh
subnet = cidr 10.0.0.0/24
address = ip 10.0.0.42

if contains subnet address:
    echo address "is inside" subnet
```

Планируемые операции:

- parse `ip` и `cidr` с ошибкой до запуска команды;
- `contains subnet address`;
- `overlaps subnet other_subnet`;
- `masked subnet`;
- сравнение и сортировка адресов;
- `next`/`prev` для адресов;
- явное получение host-адресов из CIDR.

В Go для этого достаточно стандартного `net/netip`: `Addr` — компактное
неизменяемое сравнимое значение, `Prefix` поддерживает `Contains`, `Overlaps`,
`Masked`, `Next` и `Prev`. Внешняя IP-библиотека не нужна.

## Защита от взрыва диапазона

CIDR не раскрывается в список автоматически:

```yesh
for address in hosts subnet limit 256:
    ping address
```

Правила:

- нет неограниченного `for address in subnet`;
- лимит обязателен для materialization диапазона;
- `/0`, `/1` и другие огромные диапазоны не запускают работу молча;
- превышение лимита — ошибка до запуска первой команды;
- `--plan` показывает диапазон и лимит, не перечисляя миллионы адресов.

Сетевые операции остаются маленьким встроенным модулем, а не объектной моделью
всего языка и не заменой `ip`, `ping`, `ssh` или `nmap`.
