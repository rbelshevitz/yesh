# Условия, блоки и завершение скрипта

Условие должно читаться одинаково в обычном запуске и в плане. Кавычки
отделяют текст от слов языка; ошибка проверки не означает «условие ложно».

```yesh
config = /etc/os-release
if exists $config:
    cat < config
else:
    echo "нет файла конфигурации"
    exit 2
```

Сравнение с Bash:

```bash
set -euo pipefail
config=/etc/os-release
if test -e "$config"; then
    cat < "$config"
else
    echo 'нет файла конфигурации'
    exit 2
fi
```

Правило: `exists` принимает одно строковое значение пути; отсутствие цели
даёт false, а отказ в доступе, цикл ссылок и другие ошибки останавливают скрипт.
Проверка следует символьной ссылке: ссылка на отсутствующую цель даёт false.
Список, regex, пустой путь и NUL в пути — ошибки, а не проверка текущего каталога.

Пишем только `exists path`. Старое `exists(path)` отклоняется с подсказкой
правильной формы; отдельного синтаксиса вызова функции для этой проверки нет.

## Совпадение с регулярным выражением

```yesh
service = api-42
pattern = regex '^api-[0-9]+$'
if $service matches $pattern:
    echo "подходящая служба"
```

Сравнение с Bash: `[[ "$service" =~ ^api-[0-9]+$ ]]`.
Правило: `matches` — отдельное слово между текстовым значением и regex;
слова внутри кавычек остаются данными.
Поэтому `if printf '%s' 'a matches b':` проверяет код выхода printf,
а не запускает сопоставление regex. Встроенная форма `regex '...'` справа
тоже допускается; движок и ограничения те же, что у переменной типа regex.

Ошибки: `if service matches:` не содержит шаблона; `if exists [a,b]:`
пытается передать список вместо пути. Они диагностируются с файлом и строкой.

Обычный ненулевой код внешней команды означает false. Завершение сигналом,
отмена, превышение времени и невозможность запуска остаются ошибками.
В `--plan` внешнее условие проверяется на допустимую структуру, не запускается,
а обе ветви показываются. Проверки `exists` / `matches` вычисляются без запуска
процессов; отказ доступа не скрывается и в плане.

## Завершение

```yesh
code = 7
exit $code
echo "эта строка не выполняется"
```

Сравнение с Bash: `code=7; exit "$code"`.
Правило: `exit $code` завершает весь скрипт с явно указанным десятичным
кодом от 0 до 255, в том числе внутри `if` и `for`; code 0 — успешное завершение.
Это встроенная управляющая операция, не внешний процесс и не результат `if`.

В плане exit только показывается, чтобы сохранить обзор следующих действий
и альтернативных ветвей. Ошибки: отсутствие кода, отрицательный код,
число больше 255, список, конвейер или перенаправление у exit.

## Диагностика блоков

После `if` и `for` нужны `:` и тело с отступом. `else:` допустим только
как ветвь непосредственно предшествующего `if` на том же уровне.
Ошибки заголовков обнаруживаются при разборе всего файла до выполнения команд.
Внутри строк слова `if`, `matches`, `else` и двоеточия не становятся операторами.

Отсутствие файла и отказ в просмотре родительского каталога — разные
результаты `stat`; Go позволяет проверить отсутствие через `errors.Is`.
[stat(2)](https://man7.org/linux/man-pages/man2/stat.2.html),
[os.Stat](https://pkg.go.dev/os#Stat),
[ошибки файловой системы Go](https://pkg.go.dev/io/fs#ErrNotExist).
