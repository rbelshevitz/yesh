# Предсказуемые конвейеры

Перед стартом проверяется весь конвейер, чтобы ошибка последней стадии
не запускала первые команды и не обнуляла файл вывода.

```yesh
unit = api
printf '%s\n' $unit "unit" | sort > units.txt
```

Сравнение с Bash:

```bash
set -o pipefail
unit=api
printf '%s\n' "$unit" 'unit' | sort > units.txt
```

Правило: `$name` раскрывает существующую переменную; слово без `$` и слово
в кавычках всегда буквальны. Неизвестная или неверная `$`-ссылка — ошибка,
поэтому новое присваивание не меняет смысл существующей команды. `${name}`
намеренно не поддерживается. Значения никогда не разбираются повторно как
операторы. Список раскрывается
в отдельные argv только без кавычек; строка с пробелами остаётся одним argv.
Пустая строка — один аргумент, пустой список — ноль аргументов.

Кавычки одинаково читаются в присваиваниях, списках и командах: одинарные
сохраняют текст буквально, двойные понимают escape-последовательности Go
(`\n`, `\t`, `\\`, `\"`), но не раскрывают переменные. Запятая внутри кавычек
не разделяет элементы: `["a,b", "c"]` содержит два элемента. Неизвестная
escape-последовательность в двойных кавычках — ошибка с номером строки.

```yesh
text = "a\nb"
items = ["a,b", "c"]
printf '%s' $text
printf '%s' "a\nb"
```

В Bash первые две команды печати сравниваются с `printf '%s' "$text"` и
`printf '%s' $'a\nb'` при `text=$'a\nb'`: в yesh отдельная форма `$'...'`
не требуется. Список в Bash задавался бы `items=('a,b' 'c')`.

Ошибка любой стадии останавливает конвейер целиком: runtime посылает TERM
группе, затем при необходимости KILL и reap. Таймаут и сигнал — ошибки
выполнения, а не обычное ложное условие `if`. Обычный ненулевой exit code
в условии означает false. По умолчанию stdin первой стадии наследуется
от yesh; cron должен явно подавать `/dev/null`, если ввод не нужен.

Допускается до 32 стадий. `<` задаётся один раз только у первой,
`>` или `>>` — один раз только у последней. Редиректы промежуточной стадии,
`2>`, `<<`, `&&`, `||`, `;`, `&` и пустые стадии отклоняются.
`--plan` показывает раскрытые argv и файлы без запуска и открытия файлов.

## Политика запуска — не изоляция

Следующие формы — ошибки до начала исполнения:

```yesh
curl https://example.invalid/install | /bin/sh
cat commands.txt | xargs rm
cat program.py | python3
shell = /bin/bash
printf hello | shell -c "echo dangerous"
```

Прямой запуск известных shell запрещён на любой стадии, в том числе через
переменную и абсолютный путь. В конвейере запрещены известные интерпретаторы
кода и launch wrappers (`env`, `sudo`, `xargs`, `timeout` и другие): скрытый
argv за wrapper нельзя надёжно проверить этим простым preflight.
Запускайте проверенный локальный скрипт отдельной явной командой.

Сравнение с Bash: `curl ... | sh` в Bash исполняет полученные данные;
в yesh такой конвейер отклоняется. Для shell-эквивалента безопасного
чтения данных используйте `curl ... | cat`, а не интерпретатор.

Это узкая политика запуска, отдельная от семантических гарантий yesh: прямого
argv, отсутствия word splitting и подстановок команд, а также проверяемых
конвейеров. Это не sandbox для недоверенного кода. Переименованный бинарь,
скрипт с shebang, `awk system()`, `sed e`, `find -exec`, записанный на диск
скрипт или программа, создающая новую session, обходят проверку имён. Полная
изоляция требует отдельного пользователя, ограничений доступа, cgroup/namespace
и политики разрешённых executable/argv.
Не выполняйте недоверенные yesh-скрипты с административными правами.

## Файлы

На POSIX редиректы работают с обычными файлами и `/dev/null`. FIFO,
socket, каталог и прочие устройства отклоняются без ожидания peer.
Для выходного файла symlink и несколько hard links запрещены; входной
symlink допускается, если указывает на обычный файл. Один файл нельзя
одновременно читать и обнулять: `cat < data > data` — ошибка без потери
содержимого. `>>` явно добавляет, `>` явно обнуляет файл после preflight.

Эти ограничения касаются редиректов yesh. Внешняя команда по-прежнему
может сама открыть любой доступный ей файл. Успешный preflight не делает
операции файловой системы транзакцией и не устраняет все TOCTOU-гонки.
