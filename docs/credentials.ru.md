# Credentials в yesh

## Основное правило

yesh не является хранилищем секретов. Скрипт описывает действие, а среда
выполнения предоставляет право его выполнить.

```yesh
ssh web-1 systemctl restart api
```

В этом примере yesh не читает приватный SSH-ключ. Команда `ssh` использует
обычные `ssh-agent`, `~/.ssh/config`, `IdentityFile` и `known_hosts`.

## Источники

| Источник | Назначение | Первая версия |
|---|---|---|
| OpenSSH agent/config | SSH-аутентификация | да |
| Environment | секреты CI и локального запуска | да |
| SOPS/age | зашифрованные файлы конфигурации | позже |
| Vault/secret manager | короткоживущие и динамические credentials | позже |
| OS keychain | локальные интерактивные секреты | позже |

Источники выбираются явно. yesh не сканирует окружение и не ищет секреты
автоматически.

## Минимальный API

```yesh
token = secret.env("DEPLOY_TOKEN")
deploy service with token
```

`secret.env` возвращает специальное значение `Secret`, а не обычную строку.
Позже другие источники должны иметь такую же форму:

```yesh
token = secret.vault("kv/data/app/deploy", field="token")
config = secret.sops("secrets.enc.yaml", field="app.config")
```

## Запрещённые операции

```yesh
echo token             # ошибка
url = "https://" + token  # ошибка или явное предупреждение
run command token      # запрещено, если token попадает в argv
```

Секрет можно передать только через разрешённый канал:

- environment конкретного дочернего процесса;
- stdin;
- временный файл с ограниченными правами;
- специальный credential API команды.

Секреты не должны появляться в исходниках, AST-дампах, логах, traceback,
истории команд или выводе `--plan`. В диагностике используется `<secret>`.

## SSH и host verification

SSH-аутентификация и проверка host key — разные вещи. Наличие credentials не
означает, что можно отключать проверку сервера. yesh не должен автоматически
добавлять `-o StrictHostKeyChecking=no` или менять `known_hosts`.

## MVP

Сначала реализуются только:

1. наследование `SSH_AUTH_SOCK` и обычного OpenSSH окружения;
2. явное чтение `secret.env("NAME")`;
3. redaction секретов в ошибках и логах;
4. запрет передачи `Secret` в обычные аргументы.

Vault, SOPS и другие интеграции добавляются только после появления реального
сценария и используют тот же тип `Secret`.
